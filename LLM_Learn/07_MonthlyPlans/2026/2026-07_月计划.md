# 2026-07 月计划

## 本月定位

- 阶段：`M2 revised / DeepSeek Storage Route Foundation`
- 月主题：`AI Core Storage / KVCache / 高性能分布式存储：RocksDB/LSM + io_uring/SPDK/RDMA + 推理 KVCache`
- 对当前主线的意义：把当前 DB / 存储 / 分布式系统底子转成 AI 核心系统能力；机器人 / 具身智能保留为长期 North Star 和应用牵引，不再作为短期转岗第一跳。

## 2026-06-28 修订：DeepSeek Storage 三级跳

短期职业判断调整为：

```text
分布式存储工程师
-> AI 推理工程师 / KVCache / serving / kernel 优化
-> 机器人系统工程师 / VLA runtime / robot data loop
```

理由：

- `高性能分布式存储工程师` 比纯机器人岗位更贴近当前履历：DB / 存储内核、分布式系统、性能优化和可靠性都能直接迁移。
- DeepSeek / AI Core Storage 的岗位问题足够核心：KVCache 存储、毫秒级延迟、上亿级 IOPS、分布式文件系统、对象存储、训练数据链路。
- 机器人方向仍然长期有吸引力，但短期还没到最适合切入的 turning point；更适合作为长期学习、自我探索和 AI Infra 应用牵引。
- 先进入 AI core infra，再从 KVCache / 推理服务 / 多模态 runtime 回接 VLA / robot policy runtime，比现在直接硬切机器人更稳。

执行约束：

- 7 月 P0 改为 `AI Core Storage / KVCache Storage`，不再把 Modern Robotics 作为主课。
- 机器人学习保留为 P2，每周最多一个轻量探索槽；不再用它挤占 storage / inference 主线。
- 所有系统学习都要回到 DeepSeek storage JD 的能力证据：RocksDB-style design、分布式一致性、IO path、RDMA、SSD/NVMe、KVCache lifecycle、tail latency。
- 推理系统作为第二跳提前埋线：只围绕 KVCache / prefill-decode / PagedAttention / serving scheduler，不扩散到完整训练框架。
- 论文阅读收敛到 `LLM KVCache / shared storage / 3FS / IO path`；泛 LLM、VLA、CV、Diffusion、Robot Learning 暂停主动新增，除非能直接服务 KVCache storage 或 DeepSeek 面试证据。
