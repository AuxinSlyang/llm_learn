# micrograd 代码主线复述版

## 文档定位

这份笔记用于收口 `micrograd` 第一阶段最核心的代码主线，重点不是推导高数细节，而是把 `Value`、计算图、局部 `_backward`、拓扑逆序反向传播这几件事讲顺。

当前只覆盖 `engine / Value` 这一层，后续再继续补 `nn` 部分。

---

## 1. micrograd 本质上在做什么

`micrograd` 是一个教学型的最小自动求导 / 反向传播项目。它不是为了实现完整的 PyTorch，而是为了把神经网络训练中最关键的梯度传播机制压缩到极少代码里，让我们能直接看清：

- 前向计算如何形成计算图
- 每个局部操作如何定义自己的反向传播规则
- 最终输出的梯度如何沿图反向传回所有前驱节点
- 参数为什么可以基于梯度更新

整个项目可以粗分为两部分：

- `engine`：定义 `Value`，也就是最小自动求导单元
- `nn`：基于 `Value` 组合出 `Neuron / Layer / MLP`

当前这轮 review 先聚焦 `engine`。

---

## 2. Value 的核心定位

`Value` 表面上只是一个带 `data` 和 `grad` 的标量对象，但本质上它表示的是**计算图中的一个节点**。

一个 `Value` 节点同时维护四类信息：

- `data`：当前节点在前向计算中的数值
- `grad`：当前节点对最终目标的梯度
- `_prev`：当前节点依赖的前驱节点
- `_backward`：当前节点的局部反向传播规则

所以 `Value` 不是“一个数字”，而是：

> 一个数值 + 一个局部求导规则 + 一个在计算图中的位置

---

## 3. __init__ 在做什么

`Value.__init__` 的作用不是维护一整条前向序列，而是初始化一个计算图节点。

### `self.data = data`
表示当前节点在 forward 时得到的数值结果。

### `self.grad = 0`
表示当前节点对最终目标的梯度，初始先置为 `0`。因为节点刚创建时，还没有开始反向传播，所以它的梯度尚未确定。

### `self._backward = lambda: None`
表示为局部反向传播规则预留一个默认空函数。对于叶子节点，它一开始没有局部求导逻辑；而对于后续由加法、乘法、幂运算、ReLU 等操作产生的新节点，会在对应操作内部把 `_backward` 替换成真正的局部求导规则。

### `self._prev = set(_children)`
表示当前节点依赖哪些前驱节点。它记录的不是“我影响谁”，而是“我是由谁算出来的”。

### `self._op = _op`
表示当前节点由什么操作产生，主要用于调试、可视化和帮助理解图结构。

因此，`Value` 的初始化本质上是在说：

> 创建一个计算图节点，保存当前值、未来要回传的梯度、前驱依赖关系，以及局部反向传播规则的占位符。

---

## 4. 为什么整个图天然是 DAG

每一个新的 `Value` 都只能由已经存在的旧 `Value` 通过某个局部运算生成，因此依赖关系总是从旧节点流向新节点，不会形成回环。

所以 `micrograd` 的计算图天然是一个 DAG（有向无环图）。

这个性质非常重要，因为后面的 `backward()` 需要依赖它来构造拓扑顺序；如果图里有环，反向传播的顺序就无法稳定定义。

---

## 5. __add__ / __mul__ 的本质

`__add__`、`__mul__` 这类运算不只是定义前向计算，也同时定义了对应输出节点的局部反向传播规则。

它们做了两件事：

1. 根据输入节点计算出新的 `out.data`
2. 为 `out` 绑定一个 `out._backward()`

这里的 `_backward()` 表达的不是“当前节点自己的梯度怎么求”，而是：

> 当 `out.grad` 已知时，应该如何把这份梯度按照链式法则分配回前驱节点。

这正是 `micrograd` 设计中最重要的思想：

- 前向阶段负责构图
- 每个局部节点顺手把自己的局部反向规则也记下来
- 反向阶段只需要沿图把这些局部规则依次调用起来

---

## 6. 为什么梯度更新必须用 +=

一个节点可能被多个后继节点共同依赖，因此它对最终目标的梯度不是单一路径决定的，而是所有下游路径贡献的累加。

因此局部反向传播里使用的是：

```python
self.grad += ...
```

而不是：

```python
self.grad = ...
```

这对应的本质是：

> 一个节点的总梯度，等于所有从最终输出回流到该节点的梯度贡献之和。

也正因为是累加式，`backward()` 不是幂等操作。如果对同一批节点重复执行 backward，就需要先清零已有梯度。

---

## 7. backward() 的主线

`backward()` 的工作不是直接“往前算梯度”，而是先建立一个正确的反向传播顺序，再按这个顺序依次调用每个节点的局部 `_backward()`。

它可以分成两步理解。

### 第一步：DFS 构造拓扑序

`backward()` 会从最终输出节点出发，递归访问所有前驱节点，并采用“先访问前驱，后把自己加入列表”的方式构造 `topo`。

因此得到的 `topo` 满足：

> 每个节点的前驱一定排在它前面。

`visited` 的作用是避免同一个节点被重复遍历，因为计算图是 DAG，不是树，同一个节点可能被多个后继共同依赖。

### 第二步：按拓扑逆序执行 `_backward()`

得到 `topo` 后，会先设：

```python
self.grad = 1
```

这里的 `self` 是最终调用 `backward()` 的那个输出节点。设成 1 的原因是：

> 一个变量对它自身的导数等于 1。

随后按 `reversed(topo)` 依次执行每个节点的 `_backward()`。

这样就能保证：

> 当某个节点开始把梯度传回前驱时，它自身已经先接收到了来自所有后继节点的梯度贡献。

这就是整个反向传播能正确工作的关键。

## 8. 当前这一轮最重要的收获

当前这轮 review 至少把下面这些事情重新讲顺了：

1. `micrograd` 的核心价值不是“写一个玩具库”，而是把反向传播的主线彻底暴露出来
2. `Value` 本质上是计算图节点，而不是普通数字容器
3. 每个局部操作同时定义前向值和局部反向传播规则
4. 梯度之所以要 `+=`，是因为一个节点的梯度来自多条下游路径的累加
5. `backward()` 之所以先 DFS 构造拓扑序，是为了保证后续按逆序传播梯度时顺序正确
6. `self.grad = 1` 是整个反向传播链条的起点

## 9. nn 部分：如何从 Value 组合出神经网络

如果说 `engine` 解决的是“单个计算图节点如何自动求导”，那么 `nn` 解决的就是：

> 如何基于 `Value` 这种最小自动求导单元，逐步搭出一个可以训练的全连接神经网络。

这里的核心不是新发明另一套求导机制，而是直接复用 `Value` 已经具备的：

- 前向计算构图
- 局部 `_backward()` 记录
- `loss.backward()` 自动把梯度传回所有参数

也就是说，`nn` 只是把 `Value` 组合成更高层的结构。

### 9.1 Module：统一参数与清梯度接口

`Module` 是一个很薄的基类，作用主要有两个：

- `parameters()`：返回当前模块中所有可训练参数
- `zero_grad()`：把这些参数的梯度清零

它本质上提供的是一个统一接口，使得后面不管是单个神经元、单层还是整个 MLP，都可以用同样的方式取参数、清梯度。

### 9.2 Neuron：最小神经元

`Neuron` 是最基础的可训练单元。它包含：

- 一组权重 `w`
- 一个偏置 `b`
- 一个是否使用非线性的标记 `nonlin`

这里一个神经元的输入维度是 `nin`，因此它会初始化 `nin` 个权重。每个权重和偏置都不是普通数字，而是 `Value`，这很关键，因为这意味着：

> 神经元内部的所有参数天然都在自动求导图里。

在前向调用时：

```python
act = sum((wi*xi for wi,xi in zip(self.w, x)), self.b)
return act.relu() if self.nonlin else act
```

它本质上做的是：

- 对输入向量和权重做逐元素乘法
- 再求和并加偏置
- 如果是非线性层，就再过一次 `ReLU`

也就是说，一个神经元本质上就是：

> 线性变换 `w·x + b` + 可选的非线性激活

### 9.3 Layer：一组并行神经元

`Layer` 表示一层神经网络，本质上就是多个 `Neuron(nin)` 并排放在一起。

- `nin`：每个神经元接收的输入维度
- `nout`：这一层有多少个神经元，也就有多少个输出维度

前向时：

```python
out = [n(x) for n in self.neurons]
```

表示同一个输入 `x` 同时送入这一层的所有神经元，每个神经元独立产生一个输出，因此这一层的输出就是一个向量。

所以 `Layer` 的作用可以理解为：

> 把“一个神经元”扩展成“一整层并行神经元”

### 9.4 MLP：多层感知机

`MLP` 再往上封装一层，把多个 `Layer` 串起来。

```python
sz = [nin] + nouts
self.layers = [Layer(sz[i], sz[i+1], nonlin=i!=len(nouts)-1) for i in range(len(nouts))]
```

这里：

- `nin` 是整体输入维度
- `nouts` 是每一层输出维度的列表

例如如果：

```python
MLP(3, [4, 4, 1])
```

就表示：

- 输入维度是 `3`
- 第一层：`3 -> 4`
- 第二层：`4 -> 4`
- 第三层：`4 -> 1`

因此 `MLP` 的本质就是：

> 用一串全连接层定义整个前馈神经网络的形状

其中最后一层一般不加 `ReLU`，因为输出层往往需要直接产生最终预测值，而不是再经过一次截断型非线性。

## 10. 从 MLP 到训练闭环

有了 `Value` 和 `MLP` 之后，完整训练闭环就成立了。

它的主线可以概括为：

1. 输入样本进入 `MLP`，得到模型输出
2. 基于模型输出和目标值定义 `loss`
3. 调用 `loss.backward()`，让梯度沿整张计算图回传到所有参数
4. 每个参数获得自己的 `grad`
5. 按负梯度方向更新参数
6. 下一轮前向时，模型输出和 `loss` 会发生变化

这就是神经网络训练的最小闭环。

也就是说，`micrograd` 最后真正想讲清楚的不是“写了几个类”，而是：

> 一旦参数是 `Value`，前向计算会自动构图；一旦定义了 `loss`，反向传播就会自动把梯度传回参数；一旦参数被更新，模型行为就会改变。训练就是这个闭环的重复执行。

## 11. engine 和 nn 的关系

可以把整个项目理解成两层：

### engine
回答的是：

- 一个计算图节点是什么
- 局部求导规则怎么定义
- 梯度如何沿图逆序传播

### nn
回答的是：

- 如何把这些节点组合成神经元、层和 MLP
- 如何把自动求导能力接到神经网络参数上
- 如何形成完整训练闭环

所以 `nn` 并没有脱离 `engine`，而是：

> 把 `engine` 提供的最小自动求导能力，提升到了神经网络层级。

## 14. 一版可直接复述的短总结

`micrograd` 是一个教学型的最小自动求导项目，核心价值是把反向传播从抽象口号变成代码级可见的机制。`Value` 虽然表面上只保存 `data` 和 `grad`，但本质上是计算图中的节点：它知道自己依赖哪些前驱节点，也知道在梯度回传时如何把自己的梯度传回前驱。像加法和乘法这样的局部运算，不只是算前向值，也会顺手定义自己的 `_backward()`。由于一个节点可能被多个后继共同依赖，所以梯度必须做累加，而不是覆盖。`backward()` 先通过 DFS 得到前驱在前、后继在后的拓扑序，再按逆序执行各节点的局部 `_backward()`，从而保证梯度能按照链式法则正确地从输出一路传回输入和参数节点。`nn` 部分则是在 `Value` 之上逐层封装出 `Neuron`、`Layer` 和 `MLP`，最终把自动求导能力接到神经网络参数上，形成“前向 -> loss -> backward -> 参数更新”的最小训练闭环。
