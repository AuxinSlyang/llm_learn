# makemore 六阶段学习地图

## 文档定位

这份文档是 `makemore` 项目的总览入口，用来回答三个问题：

1. `makemore` 整体到底在学什么
2. 六个阶段之间的递进关系是什么
3. 每个阶段各自要解决什么问题、留下什么产出

这份文档不负责展开所有细节，而是负责把主线拉直。

---

## makemore 整体到底在学什么

`makemore` 不只是一个“名字生成小项目”，它更像是一条非常适合入门的模型演进学习线。

它的价值在于，用同一个任务：

> `next-token prediction / 序列生成`

把一串核心模型按递进方式串起来：

- `Bigram`
- `MLP`
- `CNN / WaveNet`
- `RNN`
- `LSTM / GRU`
- `Transformer`

因此，`makemore` 的真正学习目标不是“把一个 repo 看完”，而是：

> 借由同一个任务，理解语言模型从最小统计建模到现代神经网络建模的升级路径。

---

## 六阶段主线总览

```text
阶段一：Bigram
-> 建立最小 next-token prediction 闭环

阶段二：MLP
-> 从单 token 条件概率走向固定窗口上下文 + embedding + 非线性

阶段三：CNN / WaveNet
-> 用卷积和层级感受野处理更大上下文

阶段四：RNN
-> 引入递归状态，开始显式处理序列历史

阶段五：LSTM / GRU
-> 解决 RNN 长依赖和梯度问题

阶段六：Transformer
-> 用 self-attention 替代递归，成为现代 LLM 主线结构
```

这六阶段不是彼此割裂的，而是同一个问题的不断升级：

> 怎样根据已有上下文，更好地预测下一个 token？

---

## 阶段一：Bigram

### 这一阶段在解决什么

解决最小语言模型问题：

> 给定当前 token，预测下一个 token。

即：

\[
P(ch_2 \mid ch_1)
\]

### 这一阶段的本质

- 最小条件概率建模
- 最小 next-token prediction 闭环
- 词表级别的 next-token 权重学习 / 查表式建模

### 这一阶段最重要的收获

- 理解 `xenc @ W -> logits -> probs`
- 理解训练与生成共用同一套前向
- 把 `loss / update / sample / generate` 讲顺

### 这一阶段的局限

- 只能看一个 token
- 更像查表或计数
- 泛化能力弱

### 对应文档

- `makemore-阶段一-Bigram.md`

---

## 阶段二：MLP

### 这一阶段在解决什么

解决 `Bigram` 上下文太短、泛化太弱的问题：

> 能不能看固定长度上下文，并通过可训练参数学出更强泛化？

### 这一阶段的本质

- 固定窗口上下文建模
- embedding + concatenate + hidden layer + 非线性
- 从离散计数走向连续表示学习

### 这一阶段最重要的收获

- 理解 `Bengio 2003` 的最小结构
- 理解 embedding 是可训练参数
- 理解 `hidden layer + 非线性` 为什么必要
- 理解 hidden neuron 可以看成模式探测器

### 这一阶段的局限

- 仍然是 fixed-window
- 上下文一长，参数量很快变大
- 不适合长程依赖

### 对应文档

- `makemore-阶段二-MLP.md`

---

## 阶段三：CNN / WaveNet

### 这一阶段在解决什么

解决 `MLP` 固定窗口过于僵硬、上下文扩展成本高的问题：

> 能不能用卷积结构，在参数更可控的前提下扩大感受野？

### 这一阶段要重点关注什么

- 卷积如何在序列上提取局部模式
- 多层卷积如何逐步扩大感受野
- 为什么 `WaveNet` 风格模型可以处理更长上下文

### 这一阶段要看懂的升级点

- 从“直接拼接整段上下文”
- 到“通过层级卷积逐步整合上下文”

### 当前状态

- 还未正式展开

---

## 阶段四：RNN

### 这一阶段在解决什么

解决 fixed-window 模型不自然的问题：

> 能不能不预先固定窗口，而是一步步读序列，并把历史压进一个递归状态里？

### 这一阶段要重点关注什么

- hidden state 的时间递推
- 序列历史是怎样被压进状态里的
- 为什么 RNN 天然适合序列建模

### 这一阶段要看懂的升级点

- 从“固定窗口输入”
- 到“递归更新状态”

### 当前状态

- 还未正式展开

---

## 阶段五：LSTM / GRU

### 这一阶段在解决什么

解决基础 RNN 的训练困难：

> 当序列变长时，RNN 为什么难学到长距离依赖？又该怎么缓解？

### 这一阶段要重点关注什么

- 梯度消失 / 长依赖问题
- 门控结构的意义
- `cell state` / `update gate` / `reset gate` 在做什么

### 这一阶段要看懂的升级点

- 从“有递归状态但不稳定”
- 到“通过门控机制更稳定地保留和更新信息”

### 当前状态

- 还未正式展开

---

## 阶段六：Transformer

### 这一阶段在解决什么

解决 RNN 家族串行建模和长程依赖表达的限制：

> 能不能直接让每个位置和所有位置交互，而不依赖递归链条？

### 这一阶段要重点关注什么

- self-attention 的计算逻辑
- token 表示如何被上下文动态更新
- 为什么 Transformer 更适合并行训练与长程依赖建模

### 这一阶段要看懂的升级点

- 从“靠递归链条传信息”
- 到“靠注意力直接建模任意位置之间的关系”

### 当前状态

- 还未正式展开

---

## 六阶段之间的升级逻辑

如果只用最短的话来压缩这条线，可以写成：

### 阶段一 -> 阶段二

```text
Bigram 不够
-> 只能看一个 token
-> 所以升级到 fixed-window MLP
```

### 阶段二 -> 阶段三

```text
MLP 不够
-> 上下文一长参数就膨胀
-> 所以尝试卷积方式扩大感受野
```

### 阶段三 -> 阶段四

```text
CNN / WaveNet 仍偏结构化局部聚合
-> 序列状态表达不够自然
-> 所以进入 RNN
```

### 阶段四 -> 阶段五

```text
RNN 能处理序列
-> 但长依赖和训练稳定性差
-> 所以进入 LSTM / GRU
```

### 阶段五 -> 阶段六

```text
门控 RNN 仍然串行
-> 长程依赖路径仍受限
-> 所以进入 Transformer
```

## 对当前学习阶段的判断

目前已经正式立住的内容是：

- 阶段一：`Bigram`
- 阶段二：`MLP`

这说明当前 `makemore` 项目已经具备了一个比较清楚的前两阶段骨架：

```text
最小语言模型闭环
-> embedding + MLP 的神经语言模型升级
```

对当前阶段来说，最重要的不是立刻把后四阶段全部写满，而是：

1. 先把阶段一和阶段二讲到能复述
2. 后续每推进一段，再按同样结构补对应阶段文档
3. 最终让 `makemore` 项目形成一条完整的模型演进学习线
