## **一、最终代码：一个简单的猜数字游戏**

```rust
use std::cmp::Ordering;
use std::io;

fn main() {
    println!("Guessing the number Game!");

    let secret_number = rand::random_range(1..101);
    let mut guess = String::new();
    // let apples = 10;    // immutable
    // let mut bananas = 20;   // mutable

    loop {
        guess.clear();
        println!("Please input your guess.");
        io::stdin()
            .read_line(&mut guess)
            .expect("Failed to read line");
        println!("You guess: {}", guess);

        let guess: u32 = match guess.trim().parse() {
            Ok(num) => num,
            Err(_) => continue,
        };

        match guess.cmp(&secret_number) {
            Ordering::Less => println!("Too small!"),
            Ordering::Greater => println!("Too big!"),
            Ordering::Equal => {
                println!("You win!");
                break;
            }
        }
    }
    println!("The secret number is: {}", secret_number);
}
```

> 小备注：

- > 书里用的是 rand::thread_rng().gen_range(1..=100)，需要 use rand::Rng; 并在 Cargo.toml 里加 rand = "0.8.5"。

- > 你用的是 rand::random_range(1..101)，这是 rand 新版本里的接口，Cargo.toml 里就要用对应的版本（比如 0.9.x）。

## **二、从这段代码里看 Rust 语法**

### **1. Ordering + cmp + match：把比较结果“模式匹配”掉**

你自己的理解可以直接升格成总结：
- Ordering 是一个枚举：


```
enum Ordering {
    Less,
    Greater,
    Equal,
}
```

-

- cmp 是一个比较方法：

    只要类型实现了比较（实现了 Ord / PartialOrd），就可以调用 cmp，返回一个 Ordering。

- 然后用 match 把 Ordering 的三种可能 **一一匹配并做不同处理**：


```
match guess.cmp(&secret_number) {
    Ordering::Less => println!("Too small!"),
    Ordering::Greater => println!("Too big!"),
    Ordering::Equal => {
        println!("You win!");
        break;
    }
}
```





你总结得很准：



> “简单来说就是，比较 guess 和 secret_number，然后对比较结果做模式匹配：返回什么，就执行对应的代码。”



这里可以顺带记住 match 的几个特点：

- **穷尽性**：所有可能的枚举值都必须处理，否则编译不过（帮你防 bug）。

- **模式匹配**：不仅能匹配枚举，还能匹配字面量、范围、结构体拆解等（后面学，会更爽）。

### **2. 处理用户输入：String → u32**



这一段是从“纯文本”过渡到“数字”的关键：

```
let mut guess = String::new();

io::stdin()
    .read_line(&mut guess)
    .expect("Failed to read line");

let guess: u32 = match guess.trim().parse() {
    Ok(num) => num,
    Err(_) => continue,
};
```

这里串起来的点很多：

1. String::new()：创建可变字符串缓冲区。

2. read_line(&mut guess)：

    - 往 guess 里追加用户输入

    - 返回 Result<usize, Error>，所以需要 .expect(...) 或其他错误处理方式。


3. guess.trim()：去掉首尾空白，包括回车换行。

4. .parse()：

    - 把字符串解析成某个“目标类型”

    - 由于可能失败，所以返回 Result<T, E>，这里是 Result<u32, _>。





你用 match 直接把 Result 拆开：

```
let guess: u32 = match guess.trim().parse() {
    Ok(num) => num,      // 成功：拿到数字
    Err(_) => continue,  // 失败：直接重新 loop
};
```

这里还顺带用到了“**变量遮蔽（shadowing）**”：

外层的 guess 是 String，内层的 guess 是 u32，后面的代码都直接当它是数字用。

### **3. 循环与控制流：loop / break / continue**

```
loop {
    // ...
    let guess: u32 = match guess.trim().parse() {
        Ok(num) => num,
        Err(_) => continue,
    };

    match guess.cmp(&secret_number) {
        Ordering::Less => println!("Too small!"),
        Ordering::Greater => println!("Too big!"),
        Ordering::Equal => {
            println!("You win!");
            break;
        }
    }
}
```

几个关键信息：

- loop { ... } 是一个“死循环”，只能靠 break 跳出。

- continue 会直接回到 loop 开头，重新来一轮（比如输入不是数字时）。

- break 在猜中后终止循环，游戏结束。

## **三、从这个小项目窥一眼 Cargo / crate / 版本管理**



你现在已经不只是“会用 Cargo 跑程序”，而是大致明白它在干啥了。



### **1. crate 是什么？**



书上的定义可以简单抽象成：

- **crate = 一个编译单元 / 一个包**

- 你现在的项目是一个 **binary crate**（有 fn main，能运行）

- rand 是一个 **library crate**（给别的程序用，不能自己跑）




这一点我们前面已经聊过很多，就不展开了：

“binary = 应用程序，library = 功能库”。

---

### **2. Cargo.toml：声明依赖 & 版本范围**



示例（书里的版本）：

```
[dependencies]
rand = "0.8.5"
```

这句的含义是：

- rand = "0.8.5" 等价于 ^0.8.5

- 也就是：


```
允许：>= 0.8.5 且 < 0.9.0 的任何版本
```





这是 **语义化版本（SemVer）**：

只要不跨到 0.9，就认为兼容。



你之前总结得也很对：



> Cargo.toml 里写的版本，其实是指定了“下限 + 上限（同主版本线内）”。

---

### **3. Cargo.lock：可复现构建（reproducible build）**



第一次 cargo build 时，Cargo 会：

1. 根据 Cargo.toml 的版本范围选出“符合条件的具体版本”，比如：

    - rand = 0.8.5

    - 以及它依赖的东西（rand_core、getrandom 等）


2. 把这些 **具体版本号** 写入 Cargo.lock。




以后再构建时：

- **不会重新解算版本**，而是直接用 lock 文件里的版本

- 即使 crates.io 上出了 0.8.6、0.8.7，你的项目仍然用锁定版本

- 这样你、你的队友、CI，编出来的东西是可重复的




只有你手动执行：

```
cargo update
```

Cargo 才会在**保持版本范围不变**的前提下，把依赖升级到范围内最新版本（比如从 0.8.5 → 0.8.6，而不是 0.9.0）。

---

### **4. Cargo 的“聪明”：增量编译 & 不重复干活**



书里也提到过：

- 第一次 cargo build：

    - 下载依赖

    - 编译依赖

    - 编译你的项目


- 第二次 cargo build，如果你什么都没改：

    - 只输出一行 Finished，不会重新编任何东西


- 如果你只改了 src/main.rs：

    - 只重新编译你的 binary crate

    - 依赖不会重编





你自己已经能从编译输出看出这一点，这其实已经在体验 Rust 的“构建系统哲学”了。

---

### **5. 静态链接 & 部署（顺带一提）**



我们之前聊过 Rust 为什么偏爱静态链接，这里只留一句总结在文档里：



> Rust 倾向于把依赖全部静态链接进最终二进制，

> 换来的好处是：**单个文件即可部署、无外部动态库依赖、可重复构建**，

> 代价就是二进制会大一些，但对现代环境来说完全可接受。

通过这个猜数字游戏，你已经碰到了这些核心概念：

    - match 三种情况全部处理到

    - binary crate vs library crate

    - Cargo.toml 声明依赖 & 版本范围

    - Cargo.lock 保证可复现构建

    - cargo build / run / update 的基本工作流
