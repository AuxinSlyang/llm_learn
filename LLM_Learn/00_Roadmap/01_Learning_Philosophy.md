# Learning Philosophy

> 这份文件回答的问题：**我用什么样的原则、节奏、判断标准来学？**
> 更新频率：半年级（每个 Phase 结束后复盘是否调整）；写于 2026-05-17。

## 核心原则

### 1. 完整吃透 > 数量覆盖
每个主推的东西必须学到能用自己的话讲清主链路、能脱离材料复述、最好能复现核心代码。走马观花式"看过 30 个 paper"对我没意义——真正吃透 5 个 + 复现 2 个远比扫 30 个有效。

### 2. 稳定节奏 > 突击式
长期不断比短期突击有效。不靠周末突击 8 小时补——突击式吸收率低、节奏中断后重启成本高、长期累积才能形成系统直觉。

### 3. 主推 + 副推（单焦点节奏）
同一时间窗只主推 1 条线（吃 60-70% 时间），另 1 条副推（20-30%），其余保持轻 awareness。不允许同时主推 2 条线——必塌方。

### 4. Deliverable 强约束
每月必须有可见产物：文档 / 代码 / demo。"我心里学到了" 不算——必须能拿出来。

### 5. Anchor 验证而非追逐
具体机器人场景是 anchor——用来验证能力是否到位，不是学习目标本身。不要让某个单一场景反向限制了能力本身应该怎么学。

## 时间预算

| 时段 | 投入 |
|---|---|
| 周一~周四 | 平均 1-2h / 天（核心稳定段） |
| 周五 / 周六 | 随缘，可能不看 |
| 周日 | 4-6h（周内最重段，用来集中推进或整理） |
| **周合计** | **8-14h**（中位 ~11h） |
| **月合计** | **32-56h**（中位 ~44h） |

时间分配：
- **主推线**：60-70%（约 27h / 月）
- **副推线**：20-30%（约 11h / 月）
- **buffer / 复盘 / 笔记**：5-10%（约 5h / 月）
- **经典论文 paper slot**：周一到周四白天碎片 20-40m，不计入晚上主推时间；默认只产出 takeaway 和 mini-stack 连接

容错规则：
- 单周低于预算：不补，下周继续按原节奏
- 连续 2 周低于预算 50%：触发月计划降难度审视
- 周日是节奏锚点——周日不开机 = 红色警报

## 能力分层定义（L0-L4）

| Level | 标志 | 例子 |
|---|---|---|
| **L0 地图层** | 知道它存在、解决什么、关键资料是什么 | 知道 RT-2 在做什么 |
| **L1 概念深度** | 能讲清核心算法 / 数学原理 / 设计 tradeoff | 能讲清 PPO 为什么 clip |
| **L2 实现层** | 能从零或半成品复现核心算法 | 能跑通 PPO 训 cartpole |
| **L3 实战层** | 能在新场景里组合工具解决问题 | 能用 BC 训一个 manipulation 策略 |
| **L4 专家层** | 能识别新问题、提新方法、有产出 | 有开源 / PR / paper |

今年目标：三大 Pillar 都到 L1，至少 1-2 条到 L2，至少 1 个 anchor 项目原型。

## 判断 "该不该学这个东西"

遇到新内容（paper / 课程 / 框架），按顺序问：

1. **属于哪个 Pillar / 子方向？** 不属于任何子方向 = 默认不学
2. **我当前 Level 是 L0 还是 L1？** L0 时学 survey / 教科书；L1 时学具体 paper / 代码
3. **能不能形成 deliverable？** 不能 = 降级为 awareness
4. **是不是当前 Phase 主推 / 副推线？** 不是 = 加入 reading queue，不立即开
5. **会不会挤掉当前主推的时间？** 会 = 拒绝

任何"看起来高级但和当前 Phase 无关"的内容都要警惕——它会偷走主推线的吃透深度。

## 失败 / 卡壳时的降难策略

主推线卡 1 周以上时，按顺序考虑：

1. **降细节深度**：第一遍只建直觉，证明 / 推导留 issue
2. **换材料**：教材卡 → 看 video；video 卡 → 看 blog；blog 卡 → 看代码
3. **降 deliverable 难度**：原本写完整总结 → 改成 5-10 行核心说明
4. **副推线降到 awareness**：腾出时间给主推
5. **如果还是卡**：触发月计划复审，调整或暂停该主推线

不要在卡了 2 周后还假装 on track——诚实记录卡点比维持表面进度重要。

## Sim vs Real 的边界

- **2026-06-01 修订**：Robot Learning Full-Stack 为主，LLM / AI Infra / Runtime 作为 VLA / policy runtime / edge inference 支撑线
- **机器人学习入口**：仿真优先（Gymnasium / MuJoCo 主载体），不为实物分散精力
- **实物平台**：等机器人仿真闭环、policy runtime 和数据闭环都更清楚后再评估；候选平台仍可保留 SO-100 / 低成本机械臂 / 轮式 robot
- **判断标准**：
  - 机器人仿真和 policy runtime 证据没形成前，不让实物平台分散主线
  - 机器人仿真闭环没跑通前，不投资实物
  - 仿真不能再 stress 出新问题时，才进实物

## 论文阅读节奏

- 周一到周四：每天安排一个 `paper slot`，默认 20-40m。
- 周五：汇总本周 paper takeaways，选择 1 个最值得进入项目 backlog 的 idea。
- 周末：只有当前主线需要时才精读论文，否则优先主实验 / 主编码。
- 每篇论文先按 `04_Papers/00_Reading_Workflow.md` 的 8 问模板读，不急着追公式和全部实验细节。
- 论文阅读不能挤占晚上主学习块；如果挤占，自动降级为 Scan 或跳过。
