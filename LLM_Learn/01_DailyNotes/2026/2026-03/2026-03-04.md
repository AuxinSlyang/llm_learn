## 最小加载 / 生成骨架

```python
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

model_id = "Qwen/Qwen2.5-1.5B-Instruct"

tokenizer = AutoTokenizer.from_pretrained(model_id)
messages = [
    {"role": "system", "content": "You are a helpful assistant."},
    {"role": "user", "content": "请用三句话介绍什么是 KV cache。"},
]
text = tokenizer.apply_chat_template(
    messages,
    tokenize=False,
    add_generation_prompt=True,
)

model = AutoModelForCausalLM.from_pretrained(
    model_id,
    torch_dtype=torch.float32,
).to("cuda").eval()

model.generation_config.do_sample = False
model.generation_config.temperature = 1.0
model.generation_config.top_p = 1.0
model.generation_config.top_k = 50

inputs = tokenizer([text], return_tensors="pt").to("cuda")

with torch.no_grad():
    outputs = model.generate(
        **inputs,
        max_new_tokens=96,
        use_cache=True,
        pad_token_id=tokenizer.eos_token_id,
        eos_token_id=tokenizer.eos_token_id,
    )

generated_ids = outputs[:, inputs.input_ids.shape[1]:]
response = tokenizer.batch_decode(generated_ids, skip_special_tokens=True)[0]
print(response)
```

## 今日阅读摘记

- Hugging Face / Qwen 文档 3-5 条：
  - `Qwen2.5` 至少需要 `transformers>=4.37`，否则会遇到 `qwen2` 架构无法识别的问题。
  - chat 模型的最小输入最好走 `apply_chat_template`，不要直接把原始 prompt 当成纯文本拼接。
  - 对当前这张 `V100` 来说，先用 `float32` 跑通是更稳的起点，不要默认把 `float16` 当成“应该更快也应该能跑”的前提。
  - 最小本地生成链路就是：`tokenizer -> chat template -> from_pretrained -> to(cuda) -> generate -> decode`。
  - 环境问题排查时，先分三层：`nvidia-smi`、`torch.cuda.is_available()`、`ctypes/libcuda.so.1`，这样能更快定位是在驱动层、Python runtime 还是模型层。
- Karpathy / KV Cache 文档 3-5 条：
  - 今天没有系统看完 Karpathy 视频，先把它顺延到 `03-05 / 03-06`，不和环境排障抢时间。
  - 今天对 `KV cache` 的第一层直觉来自 Qwen 最小生成链路：先处理整段输入，再逐 token 往后吐。
  - `prefill` 和 `decode` 之所以重要，是因为它们对应了“第一次把上下文吃进去”和“后续逐 token 生成”两类不同开销。
- 我能用自己的话解释的概念：
  - `token`：模型实际处理的最小离散单元，不等于一个汉字，也不一定等于一个单词。
  - `context window`：模型在当前一次生成里能同时看到的输入长度上限。
  - `logits`：模型对“下一个 token 是什么”的原始打分，还没经过 softmax。
  - `prefill`：把整段已有输入送进模型，建立中间状态和 KV cache 的阶段。
  - `decode`：在已有 KV cache 的前提下，一次只生成一个新 token 的阶段。
- 我还没讲清楚的点：
  - `Qwen2.5` 在 `V100 + float16` 上为什么会出现明显数值不稳定，后面需要再补一层硬件和算子直觉。
  - 后续 `vLLM / SGLang` 对 Python 版本、CUDA 版本的要求边界还需要在周四或周五读文档时系统整理。
