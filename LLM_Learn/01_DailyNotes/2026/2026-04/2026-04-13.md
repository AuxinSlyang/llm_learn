## makemore 第三集前半：从粗暴初始化到 Xavier / Kaiming / gain 的直觉

### 这部分到底在解决什么问题

这一段的核心不是“顺手调几个参数”，而是回答一个更基础的问题：

- 为什么一个结构上看起来没问题的 MLP，训练一开始却可能非常不健康？
- 为什么初始 loss 会异常大？
- 为什么有些神经元一开始就进入饱和区，导致梯度很难传播？
- 初始化到底应该凭经验乱调，还是应该有更系统的原则？

换句话说，这一段在补的是：`训练初期的数值状态为什么重要`。

### 1. 原始脚本的问题：初始化过于粗放

在 revisited MLP 里，如果直接使用类似下面的初始化：

- `W1 = torch.randn(...)`
- `W2 = torch.randn(...)`
- `b2 = torch.randn(...)`

那么网络一开始很容易出现两个问题：

#### 问题 A：输出层 logits 过大

`logits = h @ W2 + b2` 如果尺度过大，softmax 会变得非常尖锐。  
这时模型虽然还什么都没学会，却已经会“非常自信地乱猜”，从而导致初始 cross entropy loss 远高于随机均匀猜测应有的水平。

对于当前 27 分类问题，健康的随机起点 loss 应该大致接近：

- `log(27) ≈ 3.3`

如果一上来 loss 达到十几甚至二十几，说明初始 logits 的尺度已经失控了。

#### 问题 B：hidden 层 pre-activation 过大

如果 `hpreact = embcat @ W1 + b1` 的值很大，再送入 `tanh`：

- 很多神经元输出会接近 `1` 或 `-1`
- 进入饱和区（saturation）
- `tanh` 在这些区域导数接近 0
- 反向传播时梯度会变得极小，很难继续往前传

这会导致某些神经元对大量输入都处在近似“卡死”的状态，训练非常不健康。  
严格说这更接近 `saturated neuron`，而不是 ReLU 语境里典型的 `dead neuron`，但训练效果上会表现出“几乎传不动梯度”的问题。

### 2. Karpathy 的第一步修补：先修输出层

Karpathy 先做了一个非常朴素但有效的修补：

- `W2 = torch.randn(...) * 0.01`
- `b2 = torch.randn(...) * 0`

它的作用不是让模型“更弱”，而是让模型在训练开始时保持克制：

- `b2 = 0`：避免输出类别一开始就带随机偏置
- `W2 * 0.01`：把 logits 的初始尺度压小，避免 softmax 过于尖锐

这样模型的初始状态会更接近“谨慎的随机猜测”，而不是“极度自信但几乎全错”。  
这是为了把网络放到一个更容易被优化的起点。

### 3. 只修输出层还不够：hidden 层仍然可能饱和

即使输出层已经被压住，如果 `W1` 仍然太大，那么：

- `hpreact` 仍然会很大
- `tanh` 仍然会大量饱和
- hidden 层的梯度传播仍然会出问题

所以初始化问题不能只看 loss，还要看：

- hidden activation distribution
- pre-activation 的尺度
- 梯度是否还能顺利流动

这也是为什么后面要继续修 `W1`，甚至在有 BatchNorm 时直接把 `b1` 去掉。

### 4. 经验修补到系统原则：为什么不是随便乘一个 0.2 就结束

早期如果把 `W1` 直接乘一个较小的数，比如：

- `W1 *= 0.2`

确实能缓解一部分问题，因为 hidden pre-activation 的尺度变小了，`tanh` 的饱和情况会减轻。

但这会立刻引出一个更本质的问题：

- 为什么是 `0.2`？
- 为什么不是 `0.1`、`0.3`？
- 我们怎么知道这个初始化是“合理的”，而不是继续凭感觉乱试？

这时就自然过渡到更系统的初始化原则：

- `fan-in` 缩放
- `variance preservation`
- 针对不同激活函数的 `gain`
- Xavier / Kaiming 这类初始化直觉

### 5. 为什么最后会出现 `(5/3) / sqrt(fan_in)` 这种形式

Karpathy 最后把 `W1` 的初始化缩放到类似：

- `(5/3) / sqrt(n_embd * block_size)`

这里有两个关键信号：

#### 分母：`sqrt(fan_in)`

`fan_in = n_embd * block_size`，也就是当前层的输入维度数。  
除以 `sqrt(fan_in)`` 的核心目的是：不要让线性层输出的方差随着输入维度增加而越来越大。

#### 分子：`5/3`

这是和 `tanh` 激活函数相关的 `gain`。  
它反映的是：不同激活函数适合的初始化尺度并不一样，`tanh` 需要一个更合适的缩放来维持前向信号和梯度传播的健康状态。

所以这类初始化不是“数学花活”，而是在尽量维持：

- 前向信号不要爆炸 / 消失
- 非线性不要大面积饱和
- 反向梯度不要过早衰减

### 6. 这段内容最值得记住的主线

这一段最值得记住的不是某个具体公式，而是下面这条因果链：

1. 粗暴初始化会让 logits 和 hidden pre-activation 的尺度都不健康
2. logits 过大会让初始 loss 异常大，模型一开始就过度自信
3. hidden pre-activation 过大会让 `tanh` 饱和，梯度传播困难
4. 因此初始化不是小细节，它直接影响 activation distribution、gradient flow 和训练稳定性
5. 简单修补可以先控制输出层，但更系统的答案需要 fan-in、gain、Xavier / Kaiming 这些原则

### 7. 当前还没完全吃透的点

- `5/3` 这个 gain 的更具体数学来路
- Xavier / Kaiming 在不同激活函数下的适用差异
- BatchNorm 是如何进一步缓解初始化敏感性的
- 这些训练稳定性问题如何迁移到后续更深的网络和 Transformer 训练中
