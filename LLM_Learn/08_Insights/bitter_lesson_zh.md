# The Bitter Lesson（苦涩的教训）

作者：Rich Sutton

原文链接：<https://www.incompleteideas.net/IncIdeas/BitterLesson.html>

本文件基于仓库中的 `04_reference/Papers/bitter_lesson.pdf` 整理为中文完整译文，供学习使用。

## 中文译文

70 年 AI 研究中最重要的一条启示是：那些能够利用更多计算的方法，归根到底才是最有效的；而且，随着可用计算量的大幅增长，它们往往还会以巨大的优势胜出。其终极原因在于摩尔定律，或者更一般地说，是单位时间内可获得的计算成本会持续指数级下降。大多数 AI 研究天然是在和某个 agent 打交道，而 agent 所能利用的计算量，在一个较短的时间尺度上总是一个常数；但在更长的时间尺度上，这个常数会指数级增长。AI 研究者不可避免地会试图把这些可用计算压进系统里，以便从中获得优势。

让这条结论显得苦涩的地方在于：研究者往往试图把自己关于某个领域的知识编码进 agent 之中，但从长期看，真正起决定作用的往往不是这些人类手工注入的知识。唯一真正重要的，是那些能随着计算规模继续增长的方法，而这些方法最终会把其他一切甩开。研究者总是想让 agent 在自己知道的内容上施加影响，可一旦这么做，通常反而会阻碍方法充分利用计算能力。

在棋类程序中，这一点最明显。早期研究者曾长期依赖人类对于国际象棋的理解，试图把启发式评估、特定的局面知识和各种专家规则塞进程序里。这在短期内似乎很合理，也确实能带来一些进步。但当大规模搜索真正被用起来之后，这整套思路就被压过去了。并且，这种情况不只发生过一次：每当研究者以为“这次得靠人类知识才能继续前进”时，最终胜出的却往往是更大规模的搜索和更少的人类先验。

计算机围棋的历史也相似，只是时间更久。大家曾坚定地认为围棋和国际象棋不同，靠暴力搜索行不通，必须利用人类对于形状、厚势、死活、棋感之类的知识。但等到真正有效的方法出现时，核心仍然是搜索，只不过这次搜索和学习更紧密地结合在了一起。同样，依赖人类理解所构建的大量特定结构，最终并没有成为决定性优势。

在语音识别中，也有一段很长的时期，人们认为必须理解语音、音素、词、句法以及语言结构，才能真正取得突破。因此研究者投入了大量精力，把这些结构化知识显式写进系统里。随着统计方法的发展，尤其是那些能吃下更多数据、更多计算的方法崛起之后，这类强人工结构逐渐失去了主导地位。最终真正成功的是可以借助规模继续改进的方法，而不是那些更贴近人类直觉的手工设计。

在计算机视觉里也是这样。早期方法大量依赖边缘、广义圆柱、SIFT 特征或其他手工构造的表征。大家曾相信，视觉理解必须建立在这些由研究者精心设计的中间结构上。但当能够端到端利用大规模计算和大规模数据的学习方法成熟后，局面也发生了同样的变化。真正扩展起来并持续进步的，依旧是那些通用而可扩展的办法。

这背后有一个更一般的规律：研究者会尝试把“我们已经理解的东西”直接放进系统里，因为这能带来短期收益，也能让我们感觉自己在正确地利用知识。但从更长时间尺度看，这种做法通常会输给两类东西：`search` 和 `learning`。原因不是搜索和学习在一开始就最好，而是它们最适合随着计算规模上升而不断变强。

我们从这些历史中应该学到的，不是要反对知识、结构或理解本身，而是要警惕把它们硬编码成系统的核心机制。我们真正应该投入的是：怎样构造出能够充分利用更多计算的系统。研究者应该把注意力放在那些可扩展的元方法上，而不是沉迷于把自己当下对世界的理解写死在系统里。

从某种意义上说，这也是一条关于“如何做科学”的教训。我们应该建立那些能够自己发现、自己学习的机制，而不是试图提前把发现结果手工塞进去。把人类已有的理解直接编码进 agent，看起来像是在利用知识，实际上往往是在把系统绑死在我们当前理解的边界内。

这也是为什么这条教训是苦涩的。它苦涩，不是因为人类知识毫无价值，而是因为我们喜欢相信自己对问题结构的理解足够重要，足以成为系统性能提升的长期来源。可历史反复表明，真正长期有效的，通常是那些不依赖这种手工理解、而是依赖计算规模和数据规模不断扩展的方法。

如果我们真想在 AI 上取得持续进展，就必须接受这点：很多我们以为“本质上重要”的人工结构，最后都只是在和未来更大的计算能力竞争。短期里它们可能有帮助，长期里真正占优的还是那些最能利用计算的方法。这个结论令人不快，但过去几十年的经验已经一再证明，它大概率还会在未来继续成立。
